# Implementation Plan: GitHub Integration for Auto-Triggered PR Review

**Branch**: `010-github-app-trigger` | **Date**: 2026-06-27 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/004-github-app-trigger/spec.md`

---

## Summary

Add a GitHub App webhook receiver that auto-triggers the existing 3-agent PR review pipeline whenever a non-draft pull request is opened, pushed to, or marked ready-for-review on a configured repository. The receiver runs as a FastAPI service, verifies webhook signatures, manages one active pipeline run per PR (cancelling stale runs on new pushes), and posts the review comment directly without the HITL gate. The existing CLI path (`python -m src.pipeline`) is unchanged.

## Implementation Design

### New module: `src/webhook/signature.py`

```python
import hashlib, hmac

def verify_signature(body: bytes, secret: str, header: str | None) -> bool:
    if not header or not header.startswith("sha256="):
        return False
    expected = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header.removeprefix("sha256="))
```

### New module: `src/webhook/event_filter.py`

Parses and validates incoming GitHub webhook payloads:
- Returns `(pr_url, pr_key, installation_id, head_sha)` on success
- Returns `None` for ignored events (wrong action, draft PR, unknown fields)
- Maintains `_seen_ids: dict[str, datetime]` with 24h TTL eviction

### Modified: `src/pipeline.py`

Two new optional parameters added to `run()`:

```python
def run(
    pr_url: str,
    *,
    skip_hitl: bool = False,
    stop_event: threading.Event | None = None,
) -> PipelineState:
```

HITL gate becomes:
```python
# HITL gate (CLI path only)
if not skip_hitl:
    approved = human_approval_gate(state)
    ...
    if not approved:
        return state

# Automated path: post directly
state.posted_comment_url = post_pr_comment(...)
```

Stop-event checks after each agent (3 points):
```python
if stop_event and stop_event.is_set():
    state.error = "cancelled"
    return state
```

### New module: `src/webhook/runner.py`

Manages the asyncio task registry:
- `async def launch_run(pr_key, pr_url, installation_id)` — cancels existing run, posts "in progress" comment, starts new task
- `async def _run_task(pr_key, pr_url, stop, gh)` — calls `loop.run_in_executor(None, functools.partial(run, pr_url, skip_hitl=True, stop_event=stop))`; pipeline returns `PipelineState` without posting; runner.py posts `state.draft_comment` via `pr.create_issue_comment()` on `gh` (installation token); deletes interim comment; on exception posts error comment via `gh`; on `CancelledError` swallows silently

### New module: `src/webhook/server.py`

FastAPI app with two routes:
- `POST /webhook` — calls signature verifier, event filter, runner
- `GET /health` — returns `{"status": "ok", "active_runs": N}`

Entry point: `uv run python -m src.webhook.server`

## Triage Framework: [SYNC] vs [ASYNC] Classification

**Execution Strategy**: Hybrid — security-critical and integration components are [SYNC]; well-bounded utility modules are [ASYNC].

### Preliminary Task Classification

| Task Category | Est. [SYNC] Tasks | Est. [ASYNC] Tasks | Rationale |
|---------------|-------------------|--------------------|-----------|
| Pipeline modification | 1 | 0 | Security-adjacent (skip_hitl); surgical change to critical path |
| Webhook signature | 1 | 0 | Security-critical; constant-time comparison |
| Event filter & dedup | 0 | 1 | Well-bounded, deterministic, no security decisions |
| Async task runner | 1 | 0 | Concurrency logic + cancellation is complex/subtle |
| FastAPI server | 0 | 1 | Boilerplate route wiring; delegates logic to modules above |
| Tests | 1 | 1 | Signature + integration tests [SYNC]; filter/dedup unit tests [ASYNC] |

### Triage Audit Trail

| Task | Classification | Primary Criteria | Risk Level | Rationale |
|------|----------------|------------------|------------|-----------|
| Add `skip_hitl` + `stop_event` to `pipeline.run()` | [SYNC] | Security-critical code; modifies existing behaviour | High | HITL bypass changes safety guarantees; must be human-reviewed |
| `signature.py` — HMAC verification | [SYNC] | Security-critical; authentication | High | Incorrect timing-safe comparison opens replay/spoofing attacks |
| `event_filter.py` — action/draft/dedup logic | [ASYNC] | Well-defined deterministic rules; no security decisions | Low | Clear spec; pure functions; fully unit-testable |
| `runner.py` — asyncio task registry + cancellation | [SYNC] | Complex concurrency; threading.Event wiring | Medium | Cancellation invariants subtle; at-most-one-run rule must hold |
| `server.py` — FastAPI route wiring | [ASYNC] | Standard framework pattern; delegates to verified modules | Low | Thin glue layer; all logic in tested modules |
| Unit tests: signature, runner | [SYNC] | Validates security + concurrency guarantees | High | Human review ensures coverage is real |
| Unit tests: event filter, dedup | [ASYNC] | Standard pytest; deterministic inputs | Low | Clear assertions; no security implications |
| Integration test: webhook → pipeline | [SYNC] | Hits external API (GitHub); end-to-end trust boundary | Medium | Human review ensures test validates real behavior |
